# 数据大片：别告诉自己画什么，先想观众该有什么感觉

普通的图表回答"数据是多少"；大片回答"看的人心里该咯噔一下，还是喘不过气，还是松一口气"。
用户说的"画一张折线图""列个排名"是大白话。你的活儿是把它翻译成导演会说的话，再去写代码。

## 第一步：先问一句"感觉"，再开工

拿到数据后，先看数据里最有戏的地方（最高点、最大跌幅、反超、断崖、一直不动突然动），然后用一两句话告诉用户：

1. 这份数据里最有戏的是哪一刻。
2. 你打算让观众在那一刻有什么感觉（心跳、压迫、坏事来了、松一口气、不敢相信）。
3. 用下面的对照表，把他的大白话翻译成镜头说法，写成「大白话 → 我们可以说」。

**这三条要写在你回答的最前面，让用户看见**，格式照这个：

> 这份数据最有戏的是：……
> 我想让看的人在那一刻：……（写一种身体反应：心里咯噔一下、喘不过气、屏住呼吸、松一口气；不要写"看清趋势""感受到陡峭"）
> 画一根折线？我们可以说：……（先用对照表里的原话，再按这份数据补半句；要说清镜头怎么动）
> （其余用到的几句，也写成「大白话？我们可以说：……」）

用户问的是"列个排名""标出那天""哪个最多"这类问题时：先用一两句话把答案直接给他（排第一的是谁、是哪天、多少），**然后照样写上面那三条、照样做会动的版本**。不要因为他没说"画图"，就只交一张表格。

用户没说想要什么感觉，就自己挑一个最合适的，直接说出来让他改，不要列一堆问题反问他。

默认交付的是**会动的**：一个打开就自动播放的 HTML 页面（竖屏 1080×1920，先做最有戏的那 10 秒）。
只有用户明确说"放进报告 / PPT / 只要一张图片"，才交静态图；静态图也照上面先写那几行，再补一句"想做成视频的话可以这样拍"。
"帮我画一张折线图"不算明确要静态图。
装不上 HyperFrames 之类的工具、或者没网，也别退回静态图：直接写一个不依赖任何外部库的 HTML（canvas + requestAnimationFrame，数据直接写进页面里），打开就自动播放。

## 对照表：大白话 → 我们可以说 → 观众的感觉

| 大白话 | 我们可以说 | 观众的感觉 |
|---|---|---|
| 画一根折线 | 镜头跟着线头走，线往下掉，镜头也跟着掉 | 心跳：眼睛追着线头跑，它掉你也咯噔一下 |
| 列个排名 | 一家一块砖，越大越高，挤成一面墙；镜头从墙脚往上摇 | 压迫：排名要一行行读，大小一眼就懂 |
| 标出最大跌幅 | 跌得最惨那天劈一道闪电，墙从落点开始由红翻成绿 | 坏事来了：数字要算，闪电不用算 |
| 标出最高点 | 冲到顶的那一刻，镜头停住，四周一下子安静 | 屏住呼吸 |
| 两个东西比大小 | 并排站着，小的那个站在大的脚边，抬头看 | 差距有多大，不用读数 |
| 两条线谁超过谁 | 两个线头赛跑，反超那一刻镜头切到并排的侧面 | 不服、追上了 |
| 占比 / 饼图 | 一整块东西被切走一块，切下来那块掉下去 | 失去了多少 |
| 增长了好多倍 | 从一粒米开始，镜头一路往后退，退到看不见起点 | 不敢相信 |
| 很多年的数据 | 年份像路边的路牌一块块往后飞 | 时间很长、走了很远 |
| 一直平稳突然出事 | 前面拍得很慢很静，出事那一下画面一抖、声音停 | 意外 |

表里没有的，就照这个思路自己翻译：**把一个数字换成一个人人都有身体反应的东西**（高度、重量、天气、速度、距离、声音）。

## 第二步：写成一张短分镜，再写代码

每行写「几秒到几秒｜画面｜观众这时有什么感觉」。规矩：

- 一个镜头一个重点；前 3 秒就要有东西在动、在发生事。
- 每 1～2 秒有新东西（线画出来、东西挪开、数字跳一下），只在最有戏的那一刻停住。
- 一个主色，最多再加一个强调色（比如整体蓝、出事的地方红）。
- 数字只当配角，放在画面角落或者跟着线头走；画面主体是那个"有感觉的东西"。
- 用的是示意数据，就在画面角落标「示意数据」。

## 第三步：先做 10 秒，再一段段往后推

别一口气做完整条。先把最有戏的那 10 秒做出来给用户看，他点头了再往前后接。

做的时候常踩的坑（我们自己踩过）：

- **线不见了**：镜头离得太远或者线太细，线在大场景里一闪就没。镜头要贴着线头走，线头单独加亮。
- **整屏发白**：闪电、闪光叠在辉光上面会一起过曝。闪光单独一层、时间很短，别跟辉光叠加。
- **掉帧、一卡一卡**：别把做好的画面拉慢播放，时长变了就按新时长重新渲染。

## 最后交付时

告诉用户：最有戏的那一刻是哪儿、你让观众在那儿有什么感觉、用了表里哪几句。下次他自己就能这么说了。
